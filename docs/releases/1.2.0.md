## Atualização e operação

1. Conferir backup privado e recuperação antes da publicação e revisar as
   variáveis do ambiente. O head de migrações continua `20261101_03`, já existente
   em 1.1.0; esta promoção não acrescenta migrations.
2. Publicar API e frontend da mesma versão. Preservar o Docker Command do Render:
   `python -m app.commands.iniciar_servidor`, que aplica migrações antes do Uvicorn.
3. Antes de limitar `DATABASE_URL`, configurar `MIGRATION_DATABASE_URL`
   administrativa para o mesmo banco/schema com TLS, conferir os GRANTs e seguir
   o [roteiro de acesso PostgreSQL](../acesso-postgresql-api.md). Não usar o papel
   limitado da API para importar o catálogo.
4. A promoção coloca o workflow SIGAA em `main`. Configurar conscientemente
   secrets, ano/período e `SIGAA_PERFIL` conforme o [guia de operação](../operacao-importacao-sigaa.md).
   Sem perfil válido, a agenda não executa. Se já houver perfil válido configurado,
   a promoção pode habilitar os próximos disparos: conferir antes do merge e
   evitar importadores concorrentes. Importação manual e agendada são ações
   operacionais posteriores, não executadas pela preparação desta PR.
5. Validar `/health`, catálogo com `departamento_nome`, filtros/retorno, cadastro,
   confirmação por e-mail, login, avaliação, comparação e comentários/moderação.
   Conferir URLs, CORS, HTTPS, cookies e operação contínua do descarte. Procedimentos
   de diagnóstico e reversão em [hospedagem](../hospedagem.md).

Reverter código não restaura dados nem desfaz migrações. Não executar downgrade
automaticamente. Preservar evidências privadas sem expor segredos ou dados pessoais.
