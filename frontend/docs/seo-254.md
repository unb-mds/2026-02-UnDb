## Inventário e política aplicada

| Rotas | Indexação e canonical |
| --- | --- |
| `/` e `/sobre` | Indexáveis; canonical absoluto próprio |
| `/professores`, `/disciplinas` sem parâmetros | Indexáveis; canonical próprio; lista inicial de 100 links no HTML |
| Listas com `q`, ordenação ou demais parâmetros | `noindex, follow`; sem canonical para conteúdo de busca diferente |
| `/catalogo/{professores,disciplinas}/{pagina}` | Índice HTML paginado, links anterior/próxima; canonical de cada página; zero redireciona à lista principal |
| `/professores/{id}`, `/disciplinas/{id}` | Indexáveis; nome/código real na descrição/título; canonical usa UUID do registro |
| `/professores/{id}/disciplinas/{disciplinaId}` | Indexável; descrição dos critérios sem inventar notas; canonical próprio |
| Contexto `busca`, `q`, `ordem` nos detalhes | Navegação preservada; canonical aponta ao detalhe sem contexto, cujo conteúdo acadêmico é o mesmo |
| `/departamentos` | `noindex, follow`: catálogo interativo por query, sem páginas de unidade com identidade própria neste contrato |
| `/busca` | Encaminhamento de navegação; `noindex` no layout; destino segue a regra de lista |
| Login, cadastro, confirmação, recuperação, redefinição | `noindex`; tokens jamais no sitemap; redefinição também `no-referrer` |
| Avaliar, moderação e protótipo | `noindex, nofollow`; autorização real continua no backend |
| ID inválido/inexistente ou página de catálogo fora do limite | 404; falha de API não é convertida em ausência |

A política trata páginas e dados já públicos; não altera permissões, exposição de
identidade de estudantes, regras de avaliação ou moderação. Não há dados estruturados
`AggregateRating`, notas fictícias ou serviço pago. `robots.txt` permite rastreamento
inclusive das páginas que precisam ter seu `noindex` lido; não fornece autorização.

## Metadados, descoberta e compartilhamento

`lib/seo.ts` reutiliza a origem aprovada `https://undb.app.br` e o PNG original
`public/undb-preview.png` (1200×630) da PR #248. O guia em
`docs/referencias/preview-compartilhamento/README.md` foi conferido. Open Graph e
Twitter Card acompanham título/descrição/canonical de cada detalhe, com imagem
absoluta. Não foi produzida outra arte nem inventada conta social.

Consultas dos detalhes usam `cache` do React por renderização, compartilhando a leitura
entre `generateMetadata` e página, com o mesmo tratamento de 404 e erro. Consultar
professor/disciplina antes dos dados dependentes permanece obrigatório. O Next entrega
metadados no head inicial (`htmlLimitedBots: /.*/`), também para compartilhamento.
A espera de metadados aumenta o TTFB quando a API está lenta; falhas permanecem visíveis.

`/sitemap.xml` é um índice que aponta para `/sitemaps/paginas/0.xml` e fragmentos
`/sitemaps/{professores,disciplinas}/{n}.xml`. Cada fragmento tem até 5.000 URLs,
ordenadas por UUID, usando o catálogo real da API. IDs inválidos não entram.
Não há `lastmod` porque o contrato não fornece data de alteração de cada página.
As consultas públicas existentes retornam listas completas: a divisão limita o XML,
mas não representa paginação no banco/API. Escala maior deve evoluir esse contrato,
sem truncar silenciosamente o sitemap. Fragmento inexistente retorna 404; falha de
catálogo retorna 503 e `no-store`, nunca um sitemap vazio de sucesso.

Depois de importações, o próximo pedido reflete a API; caches compartilhados podem
reter o XML por até uma hora (`s-maxage=3600`). A ordenação estável preserva as páginas
entre pedidos de um mesmo catálogo. A navegação HTML permite descobrir detalhes e
novas páginas sem depender da busca com JavaScript. As consultas por professor e
comparação também continuam ligando aos agregados; estes não exigem N+1 no sitemap.

## Evidências e reprodução

Em 15/11/2026, HTTPS público da home consultado com curl; `/robots.txt` e
`/sitemap.xml` publicados ainda retornavam 404. Essa é evidência anterior ao deploy,
coerente com o diagnóstico da issue, e não prova que a nova implementação foi publicada.

Checks locais na base indicada:

- ESLint, TypeScript/build com `next build --webpack`: aprovados. Foi usado Webpack
  porque o Turbopack encontrou restrição de subprocesso/porta no ambiente desta sessão.
- Runner nativo do frontend: 83 testes aprovados, incluindo canonical, metadados e XML.
- `BROWSER_PATH=... node tests/seo-browser.mjs`: HTTP/HTML inicial de home,
  professor/disciplina/agregado, contexto, consulta única, noindex, links paginados,
  PNG público, robots, sitemap, 404 e falhas 503/500 aprovados com catálogo sintético.
- `node tests/preview-compartilhamento-browser.mjs`: regressão do preview/ícones da
  PR #248, com expectativas atualizadas para a lista pública de professores.
- Nova migration testada isoladamente; evidências e limites em `recuperacao-senha.md`.

Os novos runners foram acrescentados a `test:browser`. Usam a infraestrutura já
existente de Node/CDP/Edge ou Chromium, com build prévio, portas 8000/3100/9228 livres,
sem dependências novas. `PREVIEW_DIR` opcional salva o JSON da medição local.

Amostra mobile de laboratório via CDP: Brave headless, viewport 390×844, CPU 4×,
latência 150 ms, download 1,6 Mbps, upload 0,75 Mbps, cache do navegador desativado,
API sintética local e uma navegação da home. TTFB 154,3 ms; DOMContentLoaded 785,2 ms;
load 1.682,6 ms; LCP observado 908 ms. É apenas uma amostra sintética, sem score
Lighthouse, sem amostra estatística e sem dados reais de Core Web Vitals. Não estabelece
meta nem demonstra desempenho de produção, ganho de ranking ou tráfego.
